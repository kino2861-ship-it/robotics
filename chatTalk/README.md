# LINE風チャットシミュレーター

ビルド不要の静的サイトです。`index.html`、`styles.css`、`script.js`、`uni-story.js`、`story-compiler.js` を同じ階層に置いて使います。

## 初回の操作説明

いずれかのトークを初めて開くと、メッセージ欄、送信ボタン、右上のメニューを順に案内します。メニューの説明では、直近の送信を取り消す操作と、トーク全体をやり直す操作を紹介します。スマートフォンでは最後に、右スワイプまたは左上の戻るボタンでトーク一覧に戻る方法も案内します。

最後に「はじめる」を押すと、全トーク共通で説明済みの状態をブラウザーに保存します。別のトークへの移動では再表示しません。

## 最初からやり直す

メニューの「送信取り消し」→「はい」で、直近の送信とそれに続く返信を取り消し、下書きと選択肢を送信直前に戻せます。もう一度使うと、その一つ前の送信も取り消せます。返信待ちやページの再読み込み後も同じ操作ができます。更新前の履歴では、以前のバージョンが記録していた直近の1回まで戻れます。

メニューの「UNIとのトークをやり直す」を押すと、全トークのリセットを2段階で確認します。「リセットする」→「はい」を選ぶと、すべてのトーク履歴・進行状況・下書き・返信待ちと、操作説明の表示済み状態を初期化してトーク一覧に戻ります。次にいずれかのトークを開くと、操作説明が再び表示されます。

「リセットしない」「いいえ」または Escape キーで中止できます。

## 以前の相談をやり直す

トラブル一覧の「以前相談した内容について再び相談する」を開くと、以前選んだトラブルが表示されます。まだ選んだことがなければ「以前内容はありません。」と表示し、「戻る」で一覧へ戻れます。以前のトラブルを選んで送信すると、そのトラブルの会話を最初からやり直せます。過去のトーク履歴は残ります。

相談中は選択肢一覧の「他のトラブルについて相談する」で途中から一覧へ戻れます。診断コードの入力中は「選択肢を表示」から開けます。UNIの返信が終わるまでは選択肢を開いたり送信したりできません。途中で戻ったトラブルも以前の相談に残り、再び選べます。

## GitHub Pages で開く

1. ZIPを展開し、中のファイルを**フォルダーごとではなくリポジトリ直下**にアップロードします。ZIPファイル自体をアップロードしてもサイトは展開されません。
2. GitHubのリポジトリで **Settings → Pages** を開き、**Build and deployment → Source** を **Deploy from a branch** にします。
3. ブランチを `main`、フォルダーを `/(root)` にして保存します。既定のブランチ名が異なる場合は、そのブランチを選んでください。
4. Pages画面に表示されるURLをスマートフォンで開きます。反映には少し時間がかかることがあります。

GitHub公式手順: <https://docs.github.com/ja/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site>

## 会話を編集する

会話文は `uni-story.js` にまとめています。`setup` に最初の依頼と型名・資料番号・診断コードの入力、`troubleMenu.choices` にトラブル一覧の順番、`troubles` に①～⑦の会話を置いています。`script.js` は画面と保存の処理、`story-compiler.js` は台本の検査と表示用データへの変換です。文面を直すときは `uni-story.js` を編集してください。

⑦はファイルの下部に、フェーズ0の3分岐、合流後の共通返信、診断コードのフェーズ1～4、該当しないコード、停止報告の順で並べています。3分岐後の共通返信は `SELF_DESTRUCT_COMMON` に一度だけ書き、各分岐の末尾に追加しています。

各場面の `send` がこちらから送る文、`uni` がUNIから届く文です。`uni` の1要素が1つのメッセージになります。`next` に次の選択肢のIDを順番に並べ、`next: 'menu'` で通常はトラブル一覧へ戻します。文字入力を続ける場面には `nextPrompt` と `keepActive: true` を設定します。最初の返答を遅らせる場合は `waitMs` を指定します。台本のひとつの `>` に対応する文章を `uni` の1要素に入れ、メッセージ内の改行には `\n` を使います。

例えば③の流れは、`voltage-maintenance` の `send` → `uni` → `next: 'menu'` を一か所で追えます。会話を変えた後は `story-preview.html` を開き、場面を選んで文面と次の選択肢を確認できます。プレビューは本編の履歴を変更せず、待ち時間なしで表示します。存在しない分岐先や重複した選択肢などはプレビューにもエラーを表示します。

## ストーリー中に入力する文言・コード

以下は、ストーリーを進めるために入力する値の一覧です。入力欄が表示された場面で、次の値をそのまま送信してください。

| 場面 | 入力する値 | 用途 |
| --- | --- | --- |
| ロボットの型名 | `SaR2` | 修理対象の検索 |
| 修理資料の管理番号 | `681023` | 修理計画書の検索 |
| 診断コード（フェーズ1） | `E157` | 緊急時の認証処理 |
| 診断コード（フェーズ2） | `A208` | 爆弾の解除処理 |
| 診断コード（フェーズ3） | `B279` | 自爆機能の配線変更 |
| 診断コード（フェーズ4） | `A209` | 最後の電圧調整 |
| クリア前の結果コード | `M6587` | 修理失敗ルート |
| クリア前の結果コード | `S0007` | 修理成功ルート |

自爆シーケンスを停止した後は、入力欄の候補「自爆シーケンスは停止した」を送信します。診断コードの場面では、一覧にないコードを入力すると該当なしの返信になります。入力値は大文字・小文字や空白を区別しません。

会話は次の順に進みます。

1. 送信候補 `request-repair` の「修理のサポートを頼みたい。」を送ると、型名の入力に進みます。
2. `robot-model` では `SaR2` が正解です。入力のたびに「検索中…しばらくお待ちください。」を表示し、5秒後に判定結果を返します。正解時は、SaR2が開発者の個人研究機体であることと、ライブラリに修理資料が保管されている可能性を案内し、管理番号の入力に進みます。
3. `document-number` では `681023` が正解です。修理の計画書が見つかった旨などの案内を3件表示した後、トラブル内容を選べます。
4. トラブル① `screen-dark` の「ロボットの画面が暗いままで、起動ができない」は、送信して約5秒後に返信が始まり、起動ボタンの順序などを5件のメッセージで案内します。
5. `screen-on` の「画面がついた！」を送ると2件の返信が届きます。返信後、最初に選んだトラブル選択肢は一覧から消えます。
6. トラブル② `wiring-error` の「ロボットが起動したけど、画面にエラーが出ている」も、最初の返信まで約5秒待ちます。「もう少しヒントがほしい」を送るたびにヒント2、3、4へ進みます。どの段階でも「配線を直せた！」を送れます。ヒント4の後は「まだうまくいかない……」も選べます。成功時の返信後はトラブルの選択肢に戻り、トラブル②は消えます。
7. 選択肢③ `voltage-maintenance` の「電圧調整のメンテナンスについて」は、最初の返信まで約5秒待ち、ダイヤルと目標電圧について5件のメッセージで案内します。案内後は残りの選択肢に戻ります。
8. 選択肢④ `audio-maintenance` の「音声出力系のメンテナンスについて」も、最初の返信まで約5秒待ちます。案内後は追加サポートと完了報告を選べます。どちらを送っても、その会話の終了後に残りのトラブル選択肢へ戻ります。追加サポートの選択肢は再表示されません。
9. 選択肢⑤ `drive-lock` の「走行機能のロックが解除できない」は、配線状態からパスワードを考える相談です。段階的にヒントを出し、どの段階でも「ロックを解除できた！」を選べます。配線の解答を見た後に成功した場合は最初の返信だけ変わります。解答後も解決しない場合は確認事項を案内し、「ほかのトラブルについて相談する」で一覧へ戻ります。
10. 選択肢⑥ `drive-test` の「走行機能のテストについて」は、隠されたピースと2種類のパズルについて3段階でヒントを出します。どの段階でも「謎が解けた！」を選べます。ヒント3の後は「ほかのトラブルについて相談する」でも一覧に戻れます。
11. 選択肢⑦ `self-destruct-emergency` は、聞こえた内容に応じて「自爆」「自白」「賭博」の3通りに分かれ、共通の診断コード入力へ進みます。`E157`、`A208`、`B279`、`A209` は各資料を案内し、入力欄に戻ります。未知のコードは入力内容を復唱して再確認を促します。「自爆シーケンスが停止したことを報告する」を選ぶと「自爆シーケンスは停止した」を送信し、成功の返信後もコードを入力できます。

文字入力では、英字の大文字・小文字、英数字の全角・半角、前後や文字間のスペースを区別しません。該当しない入力には案内を返し、同じ質問への再入力を待ちます。

最初の依頼や各場面にある `nextPrompt` は、返信後に開く `setup.prompts` 内の質問IDです。各質問の `answers` では、`matches` に正解の入力、`replies` に正解時の返信を設定します。次の質問がある場合は `nextPromptId` にそのIDを指定します。誤答時の返信は `invalidReply` に設定します。

判定前の返信は `beforeReplies`、その返信から結果までの待ち時間は `resultDelayMs` で指定します。型名の検索では `resultDelayMs: 5000` にしています。通常の返信は最初の1通も次の1通も既定で2秒間隔とし、待つ間は3点リーダを表示します。

診断コードの場面では、返信中の `{input}` を送られた文字に置き換えます。1通ごとの待ち時間は `{ text: '返信文', delayMs: 5000 }` のように指定できます。入力中に表示する選択肢は質問の `actions` に置きます。`text` は送信文、`label` はボタン表示文です。`hideAfter` に回答IDを設定すると送信後に消えます。

トラブル相談の最初の返信は `waitMs: 5000` を指定しています。返信を待つ間は3点リーダを表示します。各場面の `next` から、相談中の選択肢や相談終了後に消す選択肢を自動的に決めます。ヒント2～4は同じ送信文でも、それぞれ別のIDで順番に進みます。ヒント3の成功選択肢だけは `labelVariants` で「配線を直せた」と表示します。走行機能の成功時の返答は `firstLineVariants` で、配線の解答を見たかどうかに応じて先頭の1件を切り替えます。

変更後は `uni-story.js` を保存し、GitHubに再アップロードしてからページを更新してください。文面を変えても既存の履歴は維持されます。過去に受信済みの文は当時のままで、変更は以後に届く返信に反映されます。進行に使うIDを変える場合は、保存データの移行または「最初から」が必要です。履歴は閲覧端末のブラウザーに保存され、端末間では同期されません。

## 画像を表示する

トークや会話プレビューの画像をタップすると、画面に合わせて拡大します。画像や周囲の余白をもう一度タップすると元の画面に戻ります。

修理成功後、祖父のトークを開いてからUNIに戻ると、エンディングの最後に記念カードが届きます。`clear-card.js` が `images/clearCard.jpg` の下部に、プレイ開始日と修理時間を `images/clear-card-glyphs.png` のドット文字で描きます。公開ページでは拡大画面の「クリアカードを保存」から `clearCard2.jpg` として保存できます。

修理時間は、初めてページを開いてから診断コード `S0007` を正しく送信するまでの経過時間です。再読み込みや同じブラウザーでの再開でも計測を引き継ぎます。「UNIとのトークをやり直す」で全履歴をリセットすると、その時点から新しいプレイを計測します。

画像ファイルを、たとえば `images` フォルダーに置きます。`uni-story.js` の画像パスは `./images/photo.jpg` のように指定します。GitHub Pagesで使う場合は画像ファイルも一緒にアップロードしてください。

相手のアイコンには `avatar` を設定します。省略すると今までどおり名前の頭文字を表示します。自分の左上のアイコンは `SELF_AVATAR` にパスを設定できます。

`opening` と `uni` に `{ image: '画像パス', alt: '画像の説明' }` を1件加えると、画像を単体のメッセージとして表示できます。文章も送る場合は、その前後に文字列を別の1件として並べます。`alt` は画像の内容を説明する短い文章です。

トラブル②のヒント3と4では `./images/port.jpg` と `./images/port2.jpg`、トラブル⑤では `./images/port2.jpg` と `./images/port3.jpg` を参照します。画像を読み込めなかった場合は「画像の表示に失敗しました」と表示されます。

場面に `image` と `alt` を設定した場合も、こちらの文章を送った後に画像を別の1件として表示します。

`.nojekyll` はGitHub Pagesがファイルをそのまま公開するための空ファイルです。日本語フォントはGoogle Fontsから読み込み、利用できない場合は端末のフォントを使います。
